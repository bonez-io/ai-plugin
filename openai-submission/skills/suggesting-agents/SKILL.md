# Suggesting agents

For clearly recurring work, first use `bonez_agent_list` to see whether an existing agent covers it. Mention that agent instead of proposing a duplicate.

Offer one concise, concrete proposal: what evidence it checks, when it runs, what it reports, and whether it would change any external records. Describe costs as run frequency unless actual pricing is known. Do not invent access to disconnected systems or suggest automatic writes without specifying them.

Suggest at most once per idea in a conversation. Accept no or silence without repeating it. A one-time fix, migration or explanation does not justify a recurring agent. An accepted proposal hands off to `creating-an-agent`, which makes any remaining consequential choices explicit before creation. Never create or run an agent merely to demonstrate the suggestion.
